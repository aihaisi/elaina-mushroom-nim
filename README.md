## 玩法规则

盘子从左到右**依次解锁**——只有最左侧未空的盘子可以取，该盘取空后才能动下一个。

- 每回合至少取 1 个，最多取走当前盘全部
- **取走最后一个蘑菇的人获胜**（正常博弈，非 Misère）

盘面随机生成：盘数 `n ∈ [3,6]`（带权，n=3 占 12.7%），每盘 `a_i ∈ [1,6]`；其中 `a_i = 1` 按 **45%** 的概率出现
（是均匀分布 `1/6 ≈ 16.67%` 的 2.7 倍，原因与实测影响见下方「出盘分布」一节）。

## 核心：这个游戏的最优解

多数人第一次玩会本能地去数"还剩几个盘子"，但正确的分析维度是**当前盘还剩几个**。

### 结构性质（博弈树归纳可证）

| 局面 | 结论 |
|---|---|
| 当前盘剩余 `m ≥ 2` | **轮到的人必胜** |
| 当前盘剩余 `m == 1` | 没有选择，只能取走；胜负取决于下一盘开局对对手是输是赢 |

为什么 `m ≥ 2` 必胜？因为面对 `m ≥ 2`，你总有两个出口，且至少一个能把败局丢出去：

1. 下一个盘子的**开局对对手是必败态** → 一次取空，把这个必败态递给他
2. 否则 → **只留 1 个**，把对手顶死在"唯一合法步"上

### 闭式解

记 `lose[j] = 「轮到某人从第 j 个盘子开始处理（该盘满额 a[j]）时，他必输」`：

```
lose[n] = true                                   // 盘面已空，无子可取者判负
lose[j] = (a[j] === 1) ? !lose[j + 1] : false    // 盘子 > 1 ⇒ 这里的人握着主动权
```

一次 `O(n)` 递推就能把整局判完，不需要搜索。

### 人能直接用的形式：数「连续 1 蘑菇盘」的奇偶

把上面那条递推展开，得到的是一条不需要写代码、当场就能用的规则。设 `r` = 「从当前位置起，紧随其后的连续『只有 1 个蘑菇』的盘子个数」：

| 局面 | 结论 |
|---|---|
| `a[j] >= 2` | **必胜**（取空 或 只留 1 个，二选一） |
| `a[j] == 1`，且这条 1 链被某个 `>= 2` 的盘截断 | 必败 当且仅当 `r` 为**奇数** |
| `a[j] == 1`，且这条 1 链一直延伸到盘尾 | 必败 当且仅当 `r` 为**偶数** |

> 实战版：面对一个 `>= 2` 的盘，只需要数**后面连着几个"只有 1 个蘑菇"的盘**——奇数就一次取空，偶数就只留 1 个。
> （末尾全为 1 时奇偶反过来，因为"盘面取空判负"把基准翻转了一次。）

这条规则也是本作**"转机"全在 1 蘑菇盘上**的正式解释：那些盘子自己没有任何选择（轮到就只能取走），
却单方面决定了前面某个 `>= 2` 的盘唯一正确的那手走法。

它的等价性由 `verify-ai.mjs` 的 I 节守着：穷举 `n ≤ 6`、`a_i ∈ [1,6]` 的全部 55986 个盘面逐个比对求解器，
外加 20000 个大值域随机盘面。

### 一个反直觉的推论

> **必败态必然是 `m == 1`，而 `m == 1` 时走法唯一。**

所以这个游戏里**不存在"必败时随机挣扎"这种设计**——最优 AI 的每一步都被唯一确定，没有概率、没有个性、没有"偶尔失误让你一局"。

这条推论直接决定了一个设计后果：**玩家一步走错，AI 接管必胜态势，再也不可挽回**。当前出盘分布下先手理论必胜率 **69.14%**——也就是说玩家先手时，走对就赢、错一步就死，而另外 **30.86% 的局开局就是死局**（这三分之一的局正是「看穿认输」机制的用武之地）。

> ⚠️ **一个反直觉的事实：这个游戏没有"多解"。**
> 对 `n ≤ 6` 的全部 **270605 个抉择局面**穷举发现：**致胜走法唯一率 = 100%**。
> 必胜局面里永远只有一个正确答案（不是"有几种赢法"），玩家做的事是**查表**而不是**选择**。
> 其中当**开局所有盘都 ≥ 2** 时，**82.6% 的唯一解是"这盘只留 1 个"**——一条可以被背下来的机械规则。
> 这决定了本作真正的思考负载**全部集中在「1 蘑菇盘」上**：只有那里才有奇偶要数。
> 出盘分布的设计目标因此不是"提高转机频率"这么简单，而是要**同时保证转机够多、且转机旁边还留着值得数的东西**（详见下文"思考负载"）。

## 出盘分布：唯一的调参入口

出盘参数集中在 `index.html` 的 `/* ==== MUSHROOM-SPAWN BEGIN/END ==== */` 块里，有两个旋钮：**蘑菇数分布**（直接写成概率）和**盘子数分布**（带权数组）。

```js
// 旋钮 1：每盘点数的分布
const ONE_MUSHROOM_CHANCE = 0.45;                                      // P(a_i = 1) = 45%
const ONE_MUSHROOM_BOOST = chanceToWeight(ONE_MUSHROOM_CHANCE, 1, 6);  // = 45/11 ≈ 4.0909

// 旋钮 2：盘子数 n 的分布（带权，n=3 被削弱但保留）
const PLATE_WEIGHTS = [
    { n: 3, weight: 0.7 },   // 短局变体：保留但不占主流
    { n: 4, weight: 1.6 },
    { n: 5, weight: 1.6 },
    { n: 6, weight: 1.6 },   // 上限由 5 提到 6：盘位越多，1 链越容易被截断
];
```

蘑菇数旋钮刻意写成「目标概率」而不是权重倍率：调参时脑子里想的是概率，反解倍率很容易算错——
**45% 对应的权重倍率是 `45/11 ≈ 4.091`，不是直觉上的 2.7**。反解公式：

$$b = \frac{k \cdot p}{1 - p} \quad (k = 5 \text{ 个其余点数档},\ p = 0.45)$$

其余五个点数等比例吸收，六档概率和恒为 100%。当前分布：**`P(a_i = 1) = 45%`，其余五档各 `11%`**。
盘子数归一化后：**n=3 占 12.73%，n=4/5/6 各 29.09%**。

### 为什么盘子数也要动：两个旋钮的性质完全不同

| 旋钮 | 对"转机" | 对"思考负载" |
|---|---|---|
| 抬高 `P(a_i = 1)` | ↑（更多 1 蘑菇盘） | **↓ 稀释**（1 蘑菇盘轮到就没得选，真判断次数被摊薄） |
| 扩大 `n` 上限 | ↑（1 链更容易被截断） | **↑ 两头都涨**（盘位更多 → 链更长 → 要数的奇偶更深） |

只抬 `P(a_i=1)` 是**零和**：35% → 50% 时真判断次数反而从 1.118 掉到 0.977。
扩 `n` 才是**两头都涨**的那个旋钮。所以这一版的取舍是：`P(a_i=1)` 只温和抬到 45%，把主要增益放在盘子数上限从 5 提到 6。

### 精确指标对照（穷举 + 概率加权，非抽样）

| 指标 | 均匀分布 | 20% 版 | 35% 版 | **当前 45% + n≤6 版** |
|---|---|---|---|---|
| `P(a_i = 1)` | 16.67% | 20.00% | 35.00% | **45.00%**（基准的 270%） |
| 盘子数取值域 | [3,5] | [3,5] | [3,5] | **[3,6]**（n=3 占 12.7%） |
| 1 蘑菇盘数 / 局 | 0.667 | 0.800 | 1.400 | **2.136** |
| 开盘就含 1 蘑菇盘的局面 | 51.24% | 58.36% | 81.03% | **92.96%** |
| 最长连续 1 蘑菇链 / 局 | 0.596 | 0.703 | 1.175 | **1.665** |
| **链长 ≥ 3 的局面占比** | — | — | 4.42% | **17.87%** |
| 先手必败率（"看穿认输"能用的局） | 14.17% | 16.48% | 25.11% | **30.86%** |
| 决策点（`m >= 2`）个数 / 局 | 3.333 | 3.200 | 2.600 | 2.609 |
| 平均蘑菇总数 / 局 | 14.00 | 13.60 | 11.80 | 12.574 |

**"链长 ≥ 3"这一行是这次真正买回来的东西。** 决策点总数几乎没动（2.600 → 2.609），
必败率从 25.1% 抬到 30.9%，但需要**数到三位以上奇偶**的局面从 4.4% 涨到 **17.9%（×4）**。
换句话说：表态次数没变，**每次表态的含金量变了**——这是"决策点"这个指标本身看不见的维度。

### 思考负载：比"决策点个数"更贴近手感的口径

早期版本我用"决策点个数"当作玩法深度，这是**概念性错误**——它只统计"玩家是否有的选"，不统计"要动多少脑"。
面对一个 ≥2 的盘，思考量取决于**它后面连着几个 1 蘑菇盘**（链越长，数奇偶越费神）。补上这个维度后的实测：

| `P(a_i=1)` | 真判断次数 / 局 | 平均链长 / 局 | 链 ≥ 3 的局面占比 |
|---|---|---|---|
| 35%（旧） | 1.118 | 0.610 | 4.42% |
| **45%（当前）** | **1.072** | **0.670** | **17.87%** |

真判断次数基本持平（−4%），但链接长度与深度都涨了。**这笔交易是正的**：玩家不会觉得抉择更少了，但每次抉择更值得算。

### 决策点分布（近半局仍只需 0~1 次抉择）

| 单局决策点个数 | 均匀分布 | 20% 版 | 35% 版 |
|---|---|---|---|
| 0 个（整局全是 1 蘑菇盘，无任何选择） | 0.18% | 0.33% | 2.10% |
| 1 个 | 2.94% | 4.27% | 13.30% |
| 2 个 | 16.50% | 19.63% | 31.18% |
| 3 个 | 37.51% | 37.55% | 33.18% |
| 4 个 | 29.47% | 27.31% | 16.36% |
| 5 个 | 13.40% | 10.92% | 3.87% |

当前档（45% + n≤6）下 0~1 决策点的局占比 **18.28%**、0 决策点 **3.14%**——
比 35% 档（15.40% / 2.10%）略差，因为 `P(a_i=1)` 毕竟又抬了 10 个点。
这是**有意的交换**：用一点点表态次数换回四分之一的"深度转机"。若还要继续加转机，
下一步该动的是**盘子数分布继续右移**（而不是继续压 `a_i`）——见下方"已知取舍"。

以上数字都是**穷举全部盘面按概率加权精确算出**的（不是抽样估计），
口径与验证器 I 节的断言一致。

## AI 是"可证最优"的，不是"测试过最优的"

`verify-ai.mjs` 一共九层验证，跑一次秒级完成：

| 层 | 内容 | 规模 |
|---|---|---|
| A · 穷举对账 | 闭式解 vs 博弈树暴力 DP，逐状态比对胜负判断 | 1364 盘面 / 15930 个可达状态 |
| B · 走法正确性 | 每个必胜步必须把对手送进必败态 | 其中 9558 个真正需要抉择的 `m ≥ 2` 局面 |
| C · 必败态唯一性 | 守住"`m == 1` 才可能必败"这条定理 | 同上 |
| D · 经典判据交叉核对 | 与"前导 1 的个数"判据等价性验证 | 全部盘面 |
| E · 大值域自对弈 | 双方均走最优，终局胜者必须等于开局裁决 | 2000 局（`n ≤ 50`、`a_i ≤ 1e6`） |
| F · 认输门控流程 | DOM 桩驱动真实页面脚本，验证门控与结算 | 13 条断言 |
| G · **官方样例对拍** | 与题面给出的期望输出逐个比对 | 5/5 |
| H · 发布副本一致性 | `site/index.html` 必须与根 `index.html` 逐字节一致 | 1 条断言 |
| I · 出盘分布与「1 蘑菇转机」 | ① 可读奇偶规则 vs 求解器等价性；② `P(a_i = 1)` 必须确为 45%、其余五档各 11%；③ **盘子数取值域必须确为 `[3,4,5,6]` 且 n=3 占比落在 10%~16%**（削弱但不得删除） | 55986 盘面穷举 + 20000 大值域随机 + 出盘概率穷举 rand 网格 |

两个容易做错的关键点：

**① 验证器不抄副本，直接从 `index.html` 里抽代码。**
求解器被显式标记在 `/* ==== MUSHROOM-SOLVER BEGIN/END ==== */` 之间，验证脚本把这整块抽出来 `new Function` 执行。测的就是真正跑在页面上的那份代码——避免"测的是副本、上的是另一版"这种经典事故。

**② G 层是唯一的"外部权威"校验。**
A~E 全都是跟"我自己写的暴力解"对账——万一我对规则的整体理解就是偏的，两边会一起错。只有题面官方样例是出题人给的独立答案，所以它单独占一层。

**③ 概率类断言穷举 rand，不做统计抽样。**
I 节要断言"`a_i = 1` 的出现率是 45%"，如果靠抽 10 万次随机数去估，抽样方差会让它偶发失败——
**一个会随机变红的断言等于没有断言**。所以出盘抽样器被写成纯函数 `pickMushroomCount(rand)` / `pickPlateCount(rand)`（随机数由外部传入），
验证器直接在 `[0,1)` 上扫一遍网格，把分布精确算出来。两个抽样器都额外断言**单调性**（`rand` 增大时抽样值不得回退）。

此外还做过**四轮变异测试**，确认断言真的会失败：

- **求解器/流程侧**：注入 6 个真实缺陷（删掉 `m ≥ 2` 判定、把取空/留 1 的分支对调、改错 `lose` 递推方向等），抓到 4 个；
  另 2 个逃逸经论证属于**等价变异**（行为保持不变），不是断言缺口。历史上真实出现过的"双重 bug"（守卫 + 置位顺序）完整复原后**被抓到**。
- **出盘分布侧（第一轮）**：注入 6 个缺陷（把倍率调回 1.0、调过头到 1.5、权重表忽略倍率、上界写错、丢掉 `lose` 的取反、盘子数上界改小），
  **6/6 全部被抓到**。这一轮还真抓出一处**断言自身的缺陷**：最早我把盘子数取值域写成"和 `MIN_PLATES`/`PLATE_SPAN` 自洽"，
  那是个恒真式——把上界从 3 悄悄改成 2 照样通过。改成钉死字面量 `[3, 4, 5]` 后才真正生效。
  同理，报告行里曾写死过一句 `✓ 与求解器完全一致`，断言失败时它仍然打印 ✓；
  **一份永远显示成功的报告比没有报告更糟**，现已改为由真实结果驱动。
- **出盘分布侧（第二轮，35% 档）**：注入 7 个缺陷（概率退回 20% / 抬到 50% / 设成 0 把一档掐死 /
  **反解公式漏掉 `(1-p)` 归一化** / 其余五档被压歪 / 抽样器忽略倍率 / 盘子数上界改小），
  **7/7 全部被抓到**。其中"漏掉归一化"只让概率从 35% 偏到 25.93%，是最隐蔽的一个——
  这类只差几个百分点的错误，只有钉死字面量的断言才拦得住。
- **出盘分布侧（第三轮，n 分布改带权 + 上限提到 6）**：注入 7 个缺陷（删掉 n=3 档 / 把 n=3 放大成主力 /
  上限退回 5 / 上限提到 7 / 权重表全改均匀 / 抽样器比较符反向 / 越界回落分支改常量），
  **7/7 全部被抓到**。本轮另注入 2 个**已论证等价**的变异（权重整体等比缩放、越界回落分支改常量）
  确认它们**存活**——前者数学上不改变归一化概率（累积概率差实测为 0），
  后者所在分支**不可达**（累积概率上限 = 1.0000000000000002 ≥ 1，而 `rand < 1` 恒成立）。
  **等价变异必须存活**，否则说明断言在钉实现细节而非契约。

## 特色机制：看穿认输

因为存在"开局即必败"的死局，原型加了一条非常规规则作为平衡器：

> 在你走出第一步之前，可以点【认输】声明"我看穿了"。
> **判对算你赢，判错算你输**；只要走过任意一步，认输资格就永久作废。

这条机制的设计要点：

- **两条路都通向"你必须真的理解局面"**：看懂死局 → 认输拿分；误判必胜局 → 认输直接输掉。猜错要付代价，否则"无脑点认输"就成了最优策略。
- **按钮文案严格中性**。早期版本会随裁决变色变字（`认输（看穿败局）` 紫色 / `认输（放弃胜利）` 橙色）——那样按钮本身就成了**答案播报器**，玩家不用思考，看一眼按钮就知道自己是不是必败局。现在必胜局与必败局显示完全一致，这条被 `verify-ai.mjs` 的 F 层用断言钉死。

> 直接发布它们会变成公开可下载的 URL。`site/` 里只有游戏本体这一个文件。
> 改完 `index.html` 记得同步：`cp index.html site/index.html`——忘了的话 H 层断言会直接失败。

`index.html` 内部划分：

| 区块 | 职责 |
|---|---|
| `MUSHROOM-SOLVER` 标记块 | `computeLosingFlags` + `analyzePosition`，博弈论核心 |
| `MUSHROOM-SPAWN` 标记块 | 出盘分布（`ONE_MUSHROOM_CHANCE` 概率旋钮 + `PLATE_WEIGHTS` 盘子数带权分布 + `chanceToWeight` 反解）+ 纯函数抽样器 |
| `aiTurn()` | 调用求解器执行最优走法 |
| `playerSurrender()` / `openingIsLosing()` | 看穿认输的判定与结算 |
| `renderBoard()` 等 | 渲染与交互 |

**AI 与玩家侧判定共用同一个 `analyzePosition`**——这是刻意的：历史上两者曾各写一套判据，导致 AI 按最优走而认输按钮给出相反裁决。

## 一个值得记下来的坑

"看穿败局 → 判胜"这个分支，第一版是**死代码**：

```js
isGameOver = true;              // ← 先置位
if (isPlayerLosing()) { ... }   // ← 而该函数自带 isGameOver 守卫 → 恒返回 false
```

不管你多准地看穿必败局，点了认输永远被判负。修法是双保险：判定函数改成**纯位置查询、不带任何外部状态守卫**，同时把判定提到置位之前。只改一处，下次还会被人改回去。

## 已知取舍（本版明确接受的代价）

出盘参数已经调过三次（均匀 → 20% → 35% → 45% + n≤6）。**边际收益在递减，且每加一次转机都要付出代价**，这些代价是有意接受的：

| 代价 | 原因 |
|---|---|
| 决策点总数不涨（2.60 徘徊） | 1 蘑菇盘轮到就没得选，抬高 `P(a_i=1)` 必然稀释表态次数 |
| 0~1 决策点的局占 18.28% | 约五分之一的对局几乎不用做决定，是"点几下看结果"的短局 |
| 整局无任何选择的局占 3.14% | 全是 1 蘑菇盘，纯看开局 |

**要不要继续调，取决于想要哪种"深"。** 三条路，代价各不相同：

1. **继续右移盘子数分布**（如把 n=3 权重再压、上限提到 7）——转机与链长还会涨，
   但 `verify-ai.mjs` 的 I 层穷举是 `n ≤ 6`，**n=7 是 2.8e5、n=8 是 1.7e6、n=9 是 1e7 个盘面**，
   验证会从秒级变成分钟级，破坏"改完就跑一遍"的反馈回路。要扩 `n`，得先想办法让验证降级取样（并接受它不再是证明）。
2. **改规则引入多解**（如允许"取任意个"以外的操作、或加不对称规则）——能真正制造"有几种赢法"的选择，
   但会同时摧毁本作最强的卖点：**AI 可证最优、且致胜走法唯一**。这是换赛道，不是调参。
3. **引入难度梯度**（让 AI 按概率走次优解）——**不建议**。它会让"我输是因为 AI 乱走"变得无法与"我走错了"区分，
   而本作的全部说服力都建立在"AI 每步唯一最优、输了就是你的问题"之上。

当前选择的是路线 1 的温和版本（只把上限提到 6、n=3 削弱不删），保住了秒级验证与"可证最优"两个性质。

## 原型题目

来自洛谷：[U145698 · C. 伊蕾娜取蘑菇](https://www.luogu.com.cn/problem/U145698)

数据范围与原型一致（`1 ≤ n ≤ 50`，`1 ≤ a_i ≤ 10^6`），求解器同样适用——闭式解是 `O(n)` 的，跟 `a_i` 的量级无关。
